# T13.3.11 — Public Form Integrity Final

**Release identity:** `r4.10.5-t13.3.11-public-form-integrity-final`  
**Application version:** `4.10.5`

## Purpose

This release closes the remaining gap between what the public forms display and what the production backend accepts. It also binds release identity to the reviewed source, removes network-fallback execution from production tooling, and limits public-form abuse-control evidence to the operationally useful retention window.

## Opening-facing corrections

- Careers applications carry the exact selected vacancy ID and title.
- The Edge Function refuses closed or nonexistent vacancies before spending a CAPTCHA token.
- Careers and Franchise programme switches are rechecked inside the same database transaction as a new submission.
- The database verifies the vacancy again inside the guarded submission transaction.
- Exact committed idempotent retries remain resolvable if a vacancy or programme closes afterward.
- Weekly availability is required in the browser, Edge Function and database boundary.
- Franchise country, city, budget and experience are required consistently at every layer.
- Public inputs use server-aligned length limits, permissive international-phone validation and browser autocomplete hints.
- Malformed request bodies and non-string field values receive a controlled rejection rather than being coerced or causing a function error.
- Customer feedback distinguishes a closed programme, closed vacancy, rate limit and verification failure without exposing internal details.
- Submission confirmations acknowledge receipt without promising a response time.
- Store cards do not render an empty Delivery section when no safe delivery URL exists.
- IP-based rate-limit identifiers use a keyed HMAC instead of a reversible unkeyed hash.
- The existing daily retention sweep deletes public-form abuse-control evidence after 30 days.

## Release and maintenance corrections

- Package scripts use locally installed, lockfile-controlled executors.
- CI and release shell scripts address `node_modules/.bin` explicitly.
- Protected release CI reads the release identity from the reviewed source; an operator may confirm it but cannot silently rename the release.
- Public-form RPC permissions are explicit: the guarded wrapper and idempotency resolver are service-role executable, while internal validators remain non-API helpers.
- A contract test prevents `npx` network fallback from returning to production lanes.

## Database change

This release appends `supabase/migration_t13311_public_form_integrity.sql` after `migration_t13310_public_boundary_cleanup.sql`. The ordered upgrade chain is now **102 migrations** and the fresh-install SQL ledger is **104 entries**.
