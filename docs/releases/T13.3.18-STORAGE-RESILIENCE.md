# T13.3.18 — Storage Resilience and Legacy-Sale Recovery

**Release identity:** `r4.10.7-t13.3.18-storage-resilience`  
**Application version:** `4.10.7`  
**Date:** 3 August 2026

This bounded source-only increment preserves T13.3.17 and closes the final known browser-storage failure path before the protected production build.

## Changes

- `tillLease.ts` now resolves `window.localStorage` inside a guarded boundary. Privacy policy, sandboxing or managed-browser restrictions can no longer crash the Staff Portal module during import.
- Where storage is unavailable and no authoritative Web Lock is available, the Till lease resolves to `secondary` and remains money-incapable. No financial operation is enabled by the fallback.
- The legacy held-sale reader now distinguishes a healthy empty queue from unavailable storage and malformed money-bearing data.
- Malformed legacy data is preserved verbatim and cannot be overwritten by `removeEntry`.
- Till orders displays a manager recovery alert and provides a download of the untouched raw value before any browser-data repair.
- A 24-check executable/static T13.3.18 contract is included in complete verification and the source-only P0 gate.

## Scope

No database migration, RLS policy, permission, role, RPC, payment authority, payroll, VAT, provider or intended business-workflow change was made. The chain remains **104 upgrade migrations / 106 fresh-install SQL entries**, with **17** deployable Edge Functions.

Production `GO` still requires the locked dependency install, official typecheck/lint/build, browser suites, PostgreSQL suites and real Supabase/Netlify commissioning in `../archive/commissioning/PRODUCTION-COMMISSIONING-T13.3.18.md`.
