# T13.3.10 — Deep Opening Final

**Release identity:** `r4.10.4-t13.3.10-opening-integrity-final`  
**Application version:** `4.10.4`

This pass closes the remaining opening-day code and source-package defects without expanding the business scope.

## Customer and owner polish

- Optional Careers, Franchise and News surfaces remain off until deliberately enabled.
- Empty menu, store and contact information renders honestly.
- Contact reasons use simple customer wording while preserving the server allowlist values.
- An empty support-route list no longer leaves a heading with no content.
- Footer metadata disappears when unconfigured and its default copy is neutral and editable.
- No browser-bundled promotion is active by default.
- The owner dashboard provides direct opening setup actions for store, menu, public contacts and launch readiness; an address alone no longer counts as a usable customer contact channel.
- Saving Launch Facts immediately refreshes the dashboard, readiness result and public configuration.
- Direct optional-section URLs wait for verified configuration instead of briefly showing a false 404.
- Missing or expired product/editorial images reveal branded artwork rather than a broken image icon.
- Owner-controlled currency values are bounded and validated before they can affect prices.
- The static shell uses UK English and neutral opening copy; Website Studio and Launch Facts primary controls meet the intended touch/readability baseline.
- Franchise wording is consistently localised to UK “enquiry” language.
- The Owner’s Guide now matches the actual Everyday / Operations / Advanced navigation and explicitly states that no native offline iPad app ships in this archive.

## Integrity and security

- Release identity is consistent across the environment template, package, tests and manifest.
- Privacy-policy URLs are validated before save and again before render.
- Phone, e-mail and external links use context-specific safe URL boundaries.
- Website publication cannot replace the menu catalogue.
- Public payloads are runtime-validated and snapshot fallback resolves per collection.
- The build-time public-configuration loader now requests the exact canonical view projection, so contact, legal and optional-section settings survive static generation and last-known-good fallback.
- Public deals and vacancies correctly accept publication-filtered view rows that omit their internal status flags, while explicit private/draft rows remain rejected.
- The canonical public-content hash now covers all customer-visible settings, site copy, menu details, stores, vacancies and published news; a changed public phone number or allergen notice can no longer be missed by the rebuild detector.
- A public brand label is no longer emitted as Schema.org `legalName` unless a distinct legal entity name has actually been entered.
- Anonymous clients can read only the canonical `public_site_configuration` view; direct access to the `site_settings` base table is revoked.
- Launch-readiness now validates e-mail, telephone and canonical-URL shape; malformed non-empty values remain incomplete and are rejected by a database trigger.
- Runtime fallback accepts `public-content.json` only when its recomputed canonical hash and collection counts match the file metadata.
- The fallback and SEO evidence files are explicitly non-cacheable across atomic deployments.
- The canonical opening URL must be a public HTTPS root domain; localhost, private-network hosts, ports, paths, queries and fragments cannot satisfy the launch gate.
- Documentation describes the fallback precisely as build-bound and hash-verified rather than independently browser-signed.
- Source-controlled brand references are verified against files on disk.
- The Website Studio content test follows the current privacy copy rather than obsolete wording.

## Source-package cleanup

- README, routing and commissioning instructions now point to one T13.3.10 authority.
- The duplicate T13.3.8 runbook and stale fourteen-function instruction are removed.
- All 17 Edge Functions and all four schedules are documented consistently.
- Historical audit bundles and redundant brand PNGs are excluded.
- The remaining historical dependency disposition is archived outside the opening root, and its workflow reference points to that archive.
- OG generation uses local fonts and local WebP artwork without network access.
- `.env.example` documents an explicit, production-impossible local fixture switch.

This release adds one append-only database migration, `migration_t13310_public_boundary_cleanup.sql`. It removes the obsolete anonymous `SELECT` grant from the private `site_settings` base table and enforces usable opening-fact shapes at the owner editor, readiness gate and database boundary. The ordered upgrade chain is now 101 migrations and the fresh-install SQL ledger is 103 entries.

This remains a source candidate. Production build, PostgreSQL and live-provider gates are mandatory before deployment.
