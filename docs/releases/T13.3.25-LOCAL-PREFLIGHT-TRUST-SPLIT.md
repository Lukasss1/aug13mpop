# T13.3.25 — Local preflight / CI trust split

T13.3.25 changes no application, database, permission or Edge Function business logic.

It corrects the public deployment handoff so the documented local `npm run public:preflight` command no longer asks an operator to copy the production Ed25519 private key out of GitHub Secrets. Local preflight still validates the release identity, domain, Supabase target, public trust policy, anti-rollback floor and production configuration. The protected GitHub `release` workflow remains the only place that requires and verifies `MP_SIGNING_KEY` before signing.

The backend workflow input now also states truthfully that it deploys the 14 public website/staff functions, not all 17 retained function sources. POS remains deferred and undeployed.
