# T13.3.19 — Release Integrity Closure

**Release identity:** `r4.10.8-t13.3.19-release-integrity`  
**Application version:** `4.10.8`  
**Date:** 4 August 2026

This bounded release closes the trust-boundary defects found after T13.3.18 without redesigning the public site, Staff Portal, Admin Panel or Web Till.

Implemented:

- one shared bounded JSON/multipart reader across all Edge request-body consumers;
- one shared defensive JWT-claims decoder after authoritative Auth verification;
- keyed anonymous pseudonyms and bounded atomic rate buckets;
- one atomic POS rate/pair transaction with retained recovery behaviour;
- invitation delivery through generated invite links and a custom provider, with no state change on unknown Auth/delivery truth;
- enable/disable through claimed recovery intents with typed partial outcomes;
- immutable clock facts and narrow server-stamped approve/reject commands;
- removal of browser clock-history legacy import and generic publication;
- checked staff-document rollback, owner-visible reconciliation and browser-dark deletion tombstones;
- corrected training-media audit columns and checked audit persistence;
- durable e-mail reservation before provider delivery and stable provider idempotency;
- direct `esbuild` ownership;
- a 31-check semantic release-integrity contract.

This source candidate still requires production database execution, live provider commissioning, browser tests, a frozen signed build and atomic deployment under `../archive/commissioning/PRODUCTION-COMMISSIONING-T13.3.19.md`.
